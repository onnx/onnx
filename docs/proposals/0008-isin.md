## Add an `Isin` operator to the ai.onnx domain

This RFC proposes adding the `Isin` operator to the ai.onnx domain.
Given two tensors `x1` and `x2`, `Isin` tests, element-wise, whether each element of `x1` is also present in `x2`, returning a boolean tensor with the same shape as `x1`.
An additional `invert` attribute toggles the semantics from testing whether an element is in `x2` to whether it is _not_ in `x2`.

The proposed semantics are identical to the `isin` function defined in the [array-API](https://data-apis.org/array-api/draft/API_specification/generated/array_api.isin.html#isin).

## Motivation

Membership testing of one tensor's elements against another is a common building block in tensor libraries (see [Prior Art section](#prior-art)), but cannot be expressed efficiently in the ONNX standard today.
One common use case for an `Isin` operation is filtering the elements of a tensor against an allow-list.
A specialized and standardized operator enables exporting more models and their preprocessing logic to ONNX.

## Proposed specification

The following description is based on the array-api documentation and has been adapted to fit the ONNX standard.

```
Tests for each element in `x1` whether the element is in `x2`.

### Attributes

**`invert`**: int (default `0`)

Integer flag indicating whether to invert the test criterion.
If non-zero, the operator **must** test whether each element in `x1` is _not_ in `x2`.
If `0`, the operator **must** test whether each element in `x1` is in `x2`.

**Notes**

- Testing whether an element in `x1` corresponds to an element in `x2` must be determined based on value equality.

### Inputs

**`x1`**: T
Input tensor whose elements are tested for membership.

**`x2`**: T
Tensor containing the values to test against.

### Outputs

**`out`**: tensor(bool)
A boolean tensor with the same shape as `x1`.

### Type Constraints

**`T`**: tensor(uint8), tensor(uint16), tensor(uint32), tensor(uint64), tensor(int8), tensor(int16), tensor(int32), tensor(int64), tensor(float16), tensor(float), tensor(double), tensor(bfloat16), tensor(string), tensor(bool)
```

## Drawbacks

This adds another operator to the standard, which needs to be tested, implemented, and maintained by downstream runtimes.
However, the operator is fairly easy to implement, and there are only a few corner cases to test.

## Rationale and alternatives

An `isin` operator can be implemented (inefficiently) using today's standard.
For example, one may broadcast-compare every element of `x1` against every element of `x2` as demonstrated in the following NumPy code that assumes one dimensional tensors for simplicity:

```
def isin(x1, x2, invert: int = 0):
    x1 = x1[:, None]  # shape(N, 1)
    x2 = x2[None, :]  # shape(1, M)
    materialized_eq = x1 == x2  # shape(N, M)
    if invert == 0:
        return materialized_eq.any(axis=1)
    return ~materialized_eq.any(axis=1)
```

This requires materializing a `N x M` boolean matrix and a subsequent reduction, which is costly in both memory and compute.
A dedicated operator can optimize this membership test (and the associated allocations) much better than this generic composition.

Alternatively, when `x2` is a small compile-time constant, membership can be unrolled into a chain of `Equal`/`Or` operators, but this does not generalize to a dynamic or large `x2`.

The `invert` attribute allows for an easy and explicit expression of a fused-negation.
The alternative to the `invert` is the usage of a subsequent `Not` node.
While runtimes may perform this fusion on the graph level, it seems significantly less complex to provide this information as an attribute.

The value `equality` requirement entails the regular floating point semantics defined in IEEE 754.
As such, `NaN` values never compare equal (including `NaN` vs `NaN`), while `-0.0` matches `0.0`.


## Prior art

The `isin` operation is common in tensor libraries.
As such, prior art is not difficult to find:

  - [array-api](https://data-apis.org/array-api/draft/API_specification/generated/array_api.isin.html#isin)
  - [NumPy](https://numpy.org/doc/stable/reference/generated/numpy.isin.html)
  - [pytorch](https://docs.pytorch.org/docs/stable/generated/torch.isin.html)
  - [tensorflow (`tf.sets`)](https://www.tensorflow.org/api_docs/python/tf/sets)
  - [jax](https://docs.jax.dev/en/latest/_autosummary/jax.numpy.isin.html)

The surveyed functions follow the array-api standard or are supersets thereof.
The array-api `isin` takes a single keyword argument, `invert`, which this proposal adopts.
NumPy and PyTorch additionally offer an `assume_unique` flag that is not part of the array-api; it is a purely-advisory hint and is omitted here.

## Unresolved questions

### Naming

The name `Isin` follows the de facto standard name of this widely used operation in the Python ecosystem (`isin`) while capitalizing the first letter to match the ONNX operator naming schema.

## Future possibilities

The `isin` operation is mature and well-established.
The here-proposed operator precisely follows the array-api operator without additional functionality.
Additional attributes such as NumPy's `assume_unique` may be added in the future in a forward compatible way.
